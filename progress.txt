What it does: a running owner escalation Live Activity now ends via an APNs
  liveactivity push the moment the escalation resolves server-side (receiver
  checks in -> process-checkin-response; owner stands down -> cancel-escalation),
  even when the owner's app is closed — instead of lingering as a stale "Overdue"
  timer on the Lock Screen until the next dashboard load.

Architecture:
  - DB: NEW additive `live_activity_push_tokens` table (token_type 'update' per-
    activity | 'start' push-to-start). Does NOT reuse/alter push_tokens or its
    platform contract (CLAUDE.md §D). Owner-scoped RLS; service role reads.
  - Edge: /register-live-activity-token upserts/deactivates tokens (family-owner
    authz for 'update'); shared/live-activity.ts endEscalationLiveActivities() is
    best-effort and never throws to the resolve handlers; apns.ts
    sendLiveActivityUpdate() uses apns-push-type liveactivity + .push-type.
    liveactivity topic, event "end" with immediate dismissal-date, content-state
    with epoch-seconds dueSince (ActivityKit decodes Date from epoch seconds).
  - iOS: EscalationActivityManager requests activities with pushType:.token and
    tracks them via LiveActivityTokenService (NSLock-guarded registry, mirrors the
    US-IOS118 LocationService pattern); observes pushTokenUpdates/activityState
    Updates to register/deactivate per-activity tokens, and pushToStartTokenUpdates
    (iOS 17.2+) to store the owner push-to-start token for a future server-start.

Backward-compat (CLAUDE.md): all changes additive. DEPLOY ORDER — edge (migration
  + endpoint, a no-op until tokens exist) must reach prod before/with the iOS build
  that registers tokens. push_tokens.platform contract untouched.

  blog-*/send-notification type errors are unrelated and predate this change). iOS
